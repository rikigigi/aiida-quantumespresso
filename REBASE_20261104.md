### Semantic breakages found in the naively rebased tree

These are the errors that a purely mechanical conflict resolution (taking the branch side
wholesale) would introduce. They must be fixed explicitly during the real rebase:

1. `parsers/neb.py`: wrong import (`parse_xml.pw.parse` instead of `parse_xml.parse`) and
   wrong call signature (`parse_pw_xml(xml_file, None)` instead of `parse_xml(xml_file)`).
2. `calculations/neb.py`: import of the removed `_lowercase_dict` helper.
3. `calculations/neb.py`: resurrected `first_structure`/`last_structure` inputs and their
   validation branch (removed upstream in `c4da42ac8`).
4. `calculations/neb.py`: resurrected `ADDITIONAL_RETRIEVE_LIST` handling (removed upstream
   in `23072e17b`).
5. `tests/calculations/test_neb.py`: tests depending on removed inputs.

Conversely, one fix must not be lost: upstream's `NebCalculation.validate_inputs` still
contains `cls.inputs = AttributeDict(value)` (a class-level attribute, i.e. shared global
state across instances — the exact bug `62becd3a2` fixes). After rebasing, this line should
be gone.

## 4. Recommended rebase strategy

1. Prepare: `git fetch aiidateam && git rebase -i aiidateam/main` on a backup of the branch.
2. In the todo list, drop:
   - `7b505a23d`, `1b7a06331`, `3b6b7c41a`, `02944a028`, `b43c51c8a`, `2f0cb3219`
     (git would skip them anyway),
   - `9624c77cd` (content-identical to upstream `2d26c649f`; patch-id differs, so git will
     NOT skip it automatically — must be dropped by hand),
   - `71ceab6e0` (xsd already upstream; git drops it automatically),
   - `63d1c13f0`, `a75685b17` (empty), `4b04bd020` (merge, linearizes away),
   - `7c0960cfd`, `db39a3d5b` (superseded by `d3df9add7` + `7a6c1204b`).
3. Resolve the five conflicts (section 3), always preferring upstream's formatting and
   re-adding only the branch's functional deltas.
4. Apply the semantic fixes of section 3 (parse_xml import/signature, remove
   `first/last_structure` support, remove `ADDITIONAL_RETRIEVE_LIST` handling, adapt the
   NEB calculation tests to `images`-only input).
5. Decide whether `c68e6b225` and `50b04af2c` (pbc workaround in `NebBaseWorkChain`) are
   still needed given upstream `9fa84b7f6`/`5f71a0296`; if not, drop them too.
6. Run `pre-commit` (Ruff) over the result: most conflicts are pure reformatting, and the
   branch's style (yapf comments, `# -*- coding -*-` headers, `numpy` vs `np`) no longer
   matches upstream.
7. Re-run the NEB/PW test suites; fixtures may need regeneration against `aiida-core ~=2.8`
   (upstream `73c0bcd6c` updated shared fixtures for the same reason).

Note: neither the dry-run tree nor the current branch was tested in this environment; the
dry run only enumerates textual conflicts. Semantic conflicts (e.g. exit-code collisions —
checked, none: 340, 320, 481-484 are all free upstream) were verified by static inspection.
